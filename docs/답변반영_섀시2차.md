# 답변반영 — 안디옥 섀시 2차 · 전송·슬롯 발견·서버 확인 (2026-11-22)

> 사본이다. 기준은 구글 드라이브 통합프로젝트 폴더의 같은 이름 문서다(총괄 세션 작성).

- 대상 의뢰서: 「검증의뢰서 — 안디옥 섀시 2차 · 전송·슬롯 발견·서버 확인 (2판)」
- 답변: 제미나이, 2026-11-22 (C1~C7, Q1~Q8, N1~N3, 급한 것 세 가지)
- 정리: 총괄 세션(ai연구소). **이 문서는 판정과 할 일의 목록이다. 코드는 안디옥 섀시 개발 세션이 고친다**(총괄 세션은 antioch 저장소에 쓸 수 없다).
- 판정 표기: **수용** · **부분 수용** · **반박**(근거) · **검증 필요**(무엇으로 확인할지) · **현행 유지**

## 0. 먼저 — 제미나이 답을 그대로 받지 않은 두 곳

1. **C1(서버 경로 바꿔치기)을 제미나이는 "틀리다, 성립하지 않는다"고 했으나 받지 않았다.** 근거로 든 Microsoft Learn 문서(QueryFullProcessImageNameW)에는 "지금 경로를 돌려준다"는 설명이 없다. 답 안에서도 "띄울 때 적어 둔 값(SeAuditProcessCreationInfo) 또는 파일 객체"라고 서로 다른 두 출처를 함께 적었다. 반대로 공개 연구(McAfee, 2019, "In NTDLL I Trust — Process Reimaging")는 Windows가 프로세스의 실행 파일 경로를 **묵은 값으로, 서로 다르게** 돌려준다고 보고했고, 그 시연은 실행 중인 파일이 든 **폴더의 이름을 바꾼 뒤 원래 자리에 다른 파일을 두는** 순서다. 어느 API가 어느 Windows 판에서 묵은 값을 주는지는 이 세션이 확인하지 못했다. → **실제로 재서 정한다(4장 M1).**
2. **Q2(핸들 넘기기, PID 재사용)를 제미나이는 각각 따로 보고 "안전하다"고 했으나, 둘을 합치면 남는다.** 가짜 프로세스 A가 파이프를 만들고 서버 핸들을 다른 프로세스 B에 넘긴 뒤 끝난다. 파이프는 B가 쥐고 있어 살아 있다. `GetNamedPipeServerProcessId` 가 "만든 프로세스의 PID"를 돌려준다면(제미나이의 설명 그대로) 그 값은 끝난 A의 PID이고, 공격자가 진짜 `netx.exe` 를 되풀이해 띄워 그 PID를 다시 받게 하면 경로 대조를 통과한다. 클라이언트 PID에 대해서는 같은 종류의 속임수가 공개돼 있다(Project Zero, 2019, "Windows Exploitation Tricks: Spoofing Named Pipe Client PID"). 서버 PID에서도 되는지는 확인하지 못했다. → **4장 M2로 잰다.**

**이 둘이 뜻하는 것:** 앱형 모듈의 서버 확인은 "등록되지 않은 프로그램이 우연히 또는 손쉽게 모듈 행세를 하는 것"을 막을 뿐, **같은 사용자 권한의 공격자에 대한 보증은 아니다.** 같은 사용자 권한이면 진짜 `netx.exe` 를 띄워 그 안에 끼어드는 길도 있다(8.3이 "못 막는 것"으로 이미 적은 경우). 그래서 방어선은 서버 확인이 아니라 **"모듈이 준 것은 자료일 뿐이고, 섀시를 거친 어떤 것도 사람의 확인 없이 실행되지 않는다"**(6.5, 6.7, 6.8)와 아래 N1~N3의 상한이다. 서버 확인을 더 두껍게 만드는 데 큰 공을 들이지 않는다.

## 2. Q1~Q8

| 항목 | 판정 | 내용 |
|---|---|---|
| Q1 서비스형 완화(D1) | **부분 수용** | 실행 파일을 확인하지 못한 채 붙은 슬롯에는 "실행 파일 미확인(session 0 만 확인)"을 보이고, 3단계에서 그 슬롯의 제안(suggest)은 받지 않는다. "session 0 의 다른 서비스가 파이프를 연다"는 그 서비스를 장악해야 하므로 관리자 권한 공격(범위 밖)에 가깝다 |
| Q1 일반 권한으로 서비스 프로세스를 열 수 있는가 | **검증 필요** | 제미나이는 "보호 프로세스가 아니면 된다"고 했고(스스로 "실기 검증 필요"라고 적음), 스토리방화벽 개발 기록에는 거부된 실측이 있다. 4장 M3 |
| Q2 핸들 넘기기 + PID 재사용 | **반박(부분)** | 0장 2번. M2 |
| Q2 프로세스 속 바꾸기(hollowing) | **반박(분류)** | 제미나이는 공격자 (나)의 일로 봤으나, 같은 사용자 권한(가)도 진짜 실행 파일을 멈춘 채 띄워 할 수 있다. 8.3의 "못 막는 것"에 해당. 0장의 결론 |
| Q3 경로 글자 비교 | **수용(한계 있음)** | "같은 파일인가"는 글자 비교 대신 **파일 식별자**(볼륨 일련번호 + 파일 번호)로 본다. 대소문자 접기 차이·하드 링크·마운트 지점의 오판이 없어진다. 다만 서버 프로세스의 파일을 **이름으로 여는 것은 그대로**라 C1의 틈은 이것으로 닫히지 않는다(제미나이의 "100% 해결"은 받지 않음). "관리자 폴더 아래인가"는 글자 비교를 유지 |
| Q4 가짜 서버가 알아내는 것 | **수용 + 검증 필요** | 서버 불일치가 되풀이되면 재시도 간격을 30초, 60초로 늘린다. 식별 수준이면 가짜 서버가 섀시 사용자의 SID·그룹을 읽을 수 있다는 지적은 맞다. 제미나이는 "서버가 클라이언트의 실행 파일을 확인해야 하므로 식별 수준이 필수"라고 했으나 **근거가 틀리다** — 상대 PID 는 가장(impersonation)과 무관하게 얻는다. 익명 수준으로 낮출 수 있는지는 모듈 서버(스토리방화벽 서비스)가 접속자의 토큰을 읽는지에 달렸다. 4장 M4 |
| Q5 알림 폭주, 닫힘 경쟁 | **수용** | `call` 이 기다리는 표에 넣은 뒤 잠금 안에서 `closed` 를 다시 본다. 읽기 스레드에 초당 알림 상한을 두고 넘는 것은 버리며 버린 수를 센다(화면 쪽 초당 10건 상한의 앞단) |
| Q6 등록부 32/64비트 보기 | **수용 → 변경 제안** | 섀시는 `KEY_WOW64_64KEY` 를 명시한다. "설치 프로그램은 64비트 보기에 쓴다"를 규격에 넣는다 — **스토리방화벽·NetX 설치 프로그램에 닿는다**(5장) |
| Q7 설치 폴더 권한(D3) | **수용** | 발견 때 한 번, 실행 파일과 그 위 폴더(Program Files 바로 아래까지)의 소유자와 DACL 을 읽어 관리자·SYSTEM·TrustedInstaller 가 아닌 주체에게 쓰기·삭제·권한 바꾸기가 허용돼 있으면 "믿지 않음(폴더 권한이 느슨함)". 제미나이는 막을 주체 셋(Users, Everyone, Authenticated Users)을 들었으나, 빠진 주체가 생기지 않게 **허용할 주체를 정하는 쪽**으로 짠다. Program Files 의 기본 권한을 러너에서 먼저 읽어 오탐이 없는지 확인 |
| Q8 `CancelIoEx` 에 NULL | **수용** | C2 와 함께. NULL 은 `PipeSink` 가 놓일 때만 |
| Q8 `reg_sz` 홀수 바이트 | **현행 유지** | 홀수면 끝 바이트가 잘리고, 깨진 UTF-16 은 `None` 이 된다. 해가 없다. 시험 한 건만 더한다 |

## 3. N1~N3 (창 열기·인계 — 3단계 설계에 쓸 것)

| 항목 | 판정 | 내용 |
|---|---|---|
| N1 섀시가 보일 것 | **수용** | 인계 단추를 누르면 섀시가 "제안한 모듈 → 받는 모듈 / 무엇을 / 어떤 대상"을 한 번 보이고 나서 넘긴다 |
| N1 섀시가 거절할 것 | **부분 수용** | 글자 걸러 내기(`..`, `\` 등) 대신 **선언한 것만 받는다**: `open.view` 는 그 모듈이 `rack.describe` 에 올린 화면 이름 가운데 하나여야 하고, `suggest.intent` 는 받는 모듈이 `rack.describe` 에 올린 "받는 일" 가운데 하나여야 한다. 자기 자신에게 하는 제안은 버린다(그건 `open` 이다). 대상이 루프백인지 같은 **옳고 그름은 받는 모듈이 판단**한다(스토리방화벽의 가드 규칙) — 섀시가 대상을 해석하기 시작하면 섀시에 보안 판단이 생긴다(4장 원칙에 어긋남). 섀시는 대상의 **형식**만 본다 |
| N2 보낸 쪽 표시 | **수용** | 받는 모듈의 확인 창에 "안디옥 섀시를 거쳐 옴 — 전달된 출처: ○○"라고 적는다. 출처 이름은 섀시가 적은 글자일 뿐임을 숨기지 않는다 |
| N2 거쳐 온 요청의 한도 | **수용 → 변경 제안** | 섀시를 거쳐 온 요청은 자동 실행하지 않는다(이미 규칙). 여기에 "영구 변경이 아니라 기한부 조치까지만"을 더할지는 받는 모듈의 정책이라 변경 제안으로 올려 기획자가 정한다 |
| N3 확인 창 쏟아 내기 | **수용 → 변경 제안** | 받는 모듈 쪽 상한 셋: 열린 확인 창이 있으면 새 요청은 거절(쌓지 않음), 한 접속자에게서 분당 3건까지, 사람이 거절한 (출처, 일, 대상)은 5분 동안 다시 띄우지 않음. 값은 초안. 여기에 더한다: 확인 창의 기본 단추는 "취소"이고, 뜬 직후 짧은 시간(예: 1초)은 키 입력을 받지 않는다(다른 일을 하다 누른 Enter 가 승인이 되지 않게) |

## 4. 재서 정할 것 (안디옥 CI 의 Windows 러너와 실기기)

안디옥 저장소는 공개라 GitHub 러너가 돈다. 아래는 문서로 확인되지 않아 **시험으로 정한다.** 결과는 판(Windows 2022, 2025, 실기기의 Windows 10·11)별로 적는다.

- **M1 (C1).** ① 사용자 폴더 `x` 에 실행 파일을 두고 띄운다. ② 폴더 `x` 의 이름을 바꾼다(되는지부터 적는다). 안 되면 실행 파일만 옮기고 `x` 를 지운다. ③ 같은 자리에 다른 폴더를 가리키는 연결(junction) `x` 를 만든다. ④ `QueryFullProcessImageNameW(PROCESS_NAME_WIN32)` 가 돌려주는 글자열을 단계마다 적는다. 함께: 짧은 이름(`PROGRA~1`)으로 띄운 프로세스가 돌려주는 글자열.
  - 묵은 경로(`…\x\…`)가 나오면 C1 은 성립한다 → "풀기 전의 값도 관리자 폴더 아래여야 한다"를 넣는다(짧은 이름 결과를 보고 모양을 정함).
  - 지금 경로가 나오면 C1 은 닫는다.
- **M2 (Q2).** 프로세스 A 가 파이프를 만들고 서버 핸들을 자식 B 에 물려준 뒤 끝난다. 클라이언트에서 `GetNamedPipeServerProcessId` 가 A 의 PID 를 주는지 B 의 PID 를 주는지 적는다.
- **M3 (Q1).** 실기기에서 일반 권한 프로세스가 스토리방화벽 서비스 프로세스를 `PROCESS_QUERY_LIMITED_INFORMATION` 으로 열 수 있는지.
- **M4 (Q4).** 스토리방화벽 서비스가 접속자의 토큰(가장)을 쓰는지 코드로 확인. 쓰지 않으면 섀시의 열기를 익명 수준으로 낮춰 다시 시험.

## 5. 변경 제안으로 올릴 것 (확정 전 — 구현 근거 아님)

규격·등록부·다른 프로그램에 닿는 것은 저장소에서 먼저 바꾸지 않는다. 기획자가 정하면 한 문서로 올린다.

1. **섀시 자신의 등록:** `HKLM\SOFTWARE\Antioch\Modules\antioch` 에 `Exe`, `Kind=chassis`. 섀시는 이 항목이 자기 자신일 때만 슬롯 목록에서 뺀다. 모듈은 이 `Exe` 를 접속자로 인정한다(8.3의 2번).
2. **등록부 보기:** 설치 프로그램은 64비트 보기에 쓴다. 읽는 쪽은 64비트 보기만 읽는다. (스토리방화벽·NetX 설치 프로그램이 지금 어느 보기에 쓰는지 각 세션이 확인)
3. **6.1 보강:** 응답의 id 는 받은 정수 그대로. 알림의 `params` 는 객체. 알림 한 줄의 상한(64KB 안).
4. **3단계 규칙(N1~N3):** 선언한 화면·일만 받기, 섀시의 중간 확인 표시, 받는 모듈의 "거쳐 옴" 표시와 상한 셋, 확인 창의 기본 단추와 입력 늦추기.
5. **서버 확인의 한계를 8.3 에 적기:** 앱형의 서버 확인은 같은 사용자 권한의 공격자에 대한 보증이 아니다(0장).

## 6. 섀시 세션이 지금 고칠 순서

1. C3 (읽기 스레드 지킴이)
2. C2 + Q8 (쓰기 시한, 자기 OVERLAPPED 만 취소, 취소 뒤 끝날 때까지 기다리기)
3. Q5 (닫힘 재확인, 읽기 스레드의 알림 상한), C4 (기다리기 줄이기), C6 (시간으로 덜기), Q8 (알림 params 객체 검사, 키 세기)
4. M1·M2 시험을 러너에 넣어 결과를 적는다 → C1 을 정한다
5. Q3 (파일 식별자 비교), Q7 (폴더 권한 검사 — 러너에서 기본 권한부터 읽기)
6. Q1 의 "실행 파일 미확인" 표시, Q6 의 `KEY_WOW64_64KEY`

5장의 것은 확정 뒤에 한다.
