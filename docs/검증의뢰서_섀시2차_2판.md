## 1. 섀시가 모듈에 붙는 순서 (구현된 그대로)

1. **발견** (`discover.rs`, 순수 함수)
   - 슬롯은 `HKLM\SOFTWARE\Antioch\Modules\<id>` 에서만 생긴다. `<id>` 는 `[a-z0-9_]{1,32}` — 틀린 이름은 값을 읽지도 않는다. 최대 32개.
   - `Kind` 는 `service`·`app` 뿐. `Exe` 는 운영체제의 최종 경로(GetFinalPathNameByHandle)로 바꾼 뒤, Program Files 폴더(SHGetKnownFolderPath 로 물은 값) 아래인지 본다. 아니면 "믿지 않음".
   - 파이프 이름: **서비스형은 HKLM 의 `PipeName` 만**, **앱형은 `HKCU\SOFTWARE\Antioch\Running\<id>\PipeName` 만** 본다. HKLM 에 없는 id 의 HKCU 값은 읽지 않는다.
   - 파이프 이름은 `\\.\pipe\<id>-<hex 32자>` 모양만 받는다. 다른 모양은 "비정상 파이프 이름"으로 두고 붙지 않는다.
   - 등록부 값은 REG_SZ 만, 1,024자까지 읽는다(RegGetValueW + RRF_RT_REG_SZ).
2. **열기** (`win::open_unchecked`)
   - `CreateFileW(이름, FILE_GENERIC_READ | FILE_WRITE_DATA | FILE_WRITE_ATTRIBUTES, …, FILE_FLAG_OVERLAPPED | SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION)` — 서버가 섀시의 토큰으로 가장(impersonate)하지 못한다.
3. **서버 확인** (`win::verify_server`) — **통과 전에는 한 바이트도 보내지 않는다**
   - `GetNamedPipeServerProcessId` → `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` → `QueryFullProcessImageNameW` → 최종 경로 → 등록된 `Exe` 의 최종 경로와 비교(`\\?\` 제거, 소문자).
   - **앱형:** 실행 파일을 알아내지 못하면 거부, 다르면 거부.
   - **서비스형:** `GetNamedPipeServerSessionId` 가 0 이어야 한다. 실행 파일을 알아낼 수 있으면 같아야 하고, **알아내지 못하면(권한 없음) session 0 + HKLM 에 공개된 이름만으로 통과시킨다.** ← 2장 D1
4. **대화** (`client.rs`)
   - `rack.hello` → 답의 `module` 이 슬롯 id 와 같고 판(메이저 같음, 마이너 이상)이 맞아야 한다. 모르는 권한 이름이 섞여 있으면 응답 전체를 버린다.
   - 한 메시지 1MB 상한(넘으면 끊음), 중첩 깊이 32 상한, JSON-RPC 2.0 응답·알림 모양이 아닌 줄은 8번까지 넘기고 그 뒤 끊는다. 서버가 보낸 "요청"은 틀린 줄로 센다.
   - 기다리는 호출이 없는 id 의 응답은 버린다. 호출마다 시한이 있다.

## 2. 구현하다 정한 것·찾은 것 (판단을 부탁합니다)

- **D1. 서비스형 서버의 실행 파일 경로 확인을 "되면 한다"로 둔 것.** 일반 권한 프로세스는 LocalSystem 서비스 프로세스를 `PROCESS_QUERY_LIMITED_INFORMATION` 으로도 열지 못할 수 있다(스토리방화벽 개발 때 같은 종류의 거부를 실측한 기록이 있다. 이 경우 자체는 **아직 실기 확인 전**). 그래서 서비스형은 "관리자만 쓰는 HKLM 의 이름 + session 0" 을 필수로, 경로 대조는 가능할 때만 한다. 3-A 답변의 "서버 Exe 경로 일치 확인"을 서비스형에서는 완화한 셈이다.
- **D2. 응답·알림에도 1MB 상한.** 6.1 은 "요청 1MB" 만 적었다. 러너 실측에서 작은 버퍼로 이어 읽는 방식에 결함이 있어(곧바로 ERROR_MORE_DATA 로 돌아온 첫 조각의 길이를 얻지 못함) 1MB+4KB 버퍼 하나로 통째로 받고, 넘으면 끊는다.
- **D3. 관리자 폴더를 Program Files 두 곳으로만 본 것.** 폴더의 ACL 을 실제로 읽어 "일반 사용자 쓰기 불가"를 확인하지는 않는다(설치 프로그램 단계의 점검으로 미룸).
- **D4. PID 로 프로세스를 여는 틈.** `GetNamedPipeServerProcessId` 가 준 PID 로 `OpenProcess` 하기 전에 그 프로세스가 끝나고 PID 가 재사용되면 다른 프로세스의 경로를 읽는다.

## 3. Claude 검수에서 이미 찾은 것 (다시 찾지 않아도 된다 — 맞는지, 어떻게 고칠지만)

코드를 짠 세션과 다른 Claude가 부록의 다섯 파일을 읽고 찾은 것이다. **확인하지 못한 것은 그렇게 적었다.**

- **C1. 앱형 서버 확인이 서버 프로세스의 경로를 "이름으로 다시 열어" 푼다 — 가장 먼저 봐 달라. [확인하지 못함]**
  `verify_server` 는 `process_image(pid)` 가 돌려준 경로 글자열을 `final_path` 로 **다시 열어** 연결·짧은 이름을 푼 뒤 등록된 Exe 와 비교한다. 그 글자열이 가리키는 파일은 프로세스가 뜬 뒤에 바뀔 수 있다. 걱정하는 순서:
  1. 공격자(가)가 `C:\Users\me\x\netx.exe`(가짜)를 띄운다. 이 프로세스가 `\\.\pipe\netx-<hex>` 를 만들고 HKCU 의 실행 중 값에 그 이름을 쓴다.
  2. 실행 중인 `netx.exe` 를 다른 폴더로 옮긴다(실행 중인 파일의 이름 바꾸기는 허용되는 것으로 안다). 빈 폴더 `x` 를 지우고, 같은 자리에 `C:\Program Files\NetX` 를 가리키는 **디렉터리 연결(junction)** 을 만든다(일반 권한으로 된다).
  3. 섀시가 붙는다. `QueryFullProcessImageNameW` 가 **띄울 때의 경로** `C:\Users\me\x\netx.exe` 를 돌려준다면, `final_path` 는 연결을 따라가 `C:\Program Files\NetX\netx.exe` 를 내놓고 `same_path` 가 참이 된다. 가짜 서버가 NetX 로 통과한다(프로세스에 끼어들지 않고도).
  - 이것이 되는지는 `QueryFullProcessImageNameW(PROCESS_NAME_WIN32)` 가 "띄울 때 적어 둔 이름"을 주는지 "파일의 지금 이름"을 주는지에 달려 있다. **어느 쪽인지 확인하지 못했다.** 아는 대로, 근거와 함께 적어 달라.
  - 생각한 고침: 서버 프로세스의 경로는 **풀기 전의 값 그대로도** 관리자 폴더 아래여야 하고, 풀기 전의 값과 푼 값이 (비교용 모양으로) 같아야 통과시킨다. 진짜 NetX 는 Program Files 에서 떴으므로 풀기 전 경로가 이미 그 아래다. 이 고침이 정상 설치(짧은 이름으로 띄운 경우, 다른 드라이브에 Program Files 가 있는 경우)를 막는 일이 있는가? 더 나은 방법(파일 식별자 비교 등)이 있는가?
- **C2. 호출 시한이 "쓰기"를 덮지 않는다.** `Client::call` 은 `write_line` 이 끝난 뒤에야 `recv_timeout` 을 센다. `PipeSink::write_line` 은 `GetOverlappedResult(…, bWait=TRUE)` 로 끝까지 기다린다. 서버가 읽지 않아 파이프 버퍼가 차면 부른 스레드가 시한 없이 멈추고, 쓰기 잠금(`sink` 뮤텍스)을 기다리는 다른 호출도 함께 멈춘다. 요청이 작고(1KB 안쪽) 섀시가 첫 시한 초과에 연결을 끊으므로 실제로 차기는 어렵다고 봤다. 그래도 쓰기에 시한을 걸어야 하는가(`WaitForSingleObject` + `CancelIoEx`)?
- **C3. 알림 콜백이 죽으면 연결이 "살아 있는 것처럼" 남는다.** 읽기 스레드는 `on_notify` 를 그대로 부른다. 콜백이 모듈이 보낸 자료 때문에 패닉하면 스레드가 끝나는데, `closed` 깃발도 서지 않고 `on_close` 도 불리지 않는다. 그 뒤의 호출은 시한 초과로만 끝난다. 놓일 때 깃발을 세우는 지킴이(drop guard)나 `catch_unwind` 가 필요하다고 본다.
- **C4. 파이프 열기가 한 슬롯에서 6초까지 멈출 수 있다.** `open_unchecked` 는 `ERROR_PIPE_BUSY` 면 `WaitNamedPipeW(2초)` 를 세 번까지 한다. 공격자(가)가 형식이 맞는 가짜 이름을 HKCU 에 쓰고 그 파이프의 인스턴스를 모두 잡아 두면, 발견·연결이 한 줄로 돌 때 다른 슬롯까지 늦어진다(1차 반영의 "시도 간격 2초 이상"은 있다).
- **C5. 길이 0 인 메시지를 "상대가 닫음"으로 본다**(`PipeLine::read_line` 의 `n == 0`). 서버가 스스로 끊긴 척할 수 있을 뿐이라 해가 없다고 봤다.
- **C6. 틀린 줄 세기(`MAX_BAD_LINES = 8`)가 연결이 살아 있는 동안 0 으로 돌아가지 않는다.** 오래 붙어 있는 정상 모듈이 드물게 낸 틀린 줄이 쌓이면 끊긴다. 의도한 엄격함이지만, 시간이 지나면 덜어 주는 것이 맞는지 의견을 달라.
- **C7. 섀시 자신의 등록 자리가 코드에 없다. [설계 빈칸]** 8.3 은 서로 확인(상호)이다. 모듈은 접속해 온 프로세스의 실행 파일이 등록부의 `Exe`·`ClientExe` 가운데 하나일 때만 `read` 를 준다. 그러면 섀시도 `HKLM\…\Modules\<id>` 에 올라야 하는데, `discover` 는 그 항목을 슬롯으로 보고 `Kind` 가 없으면 "믿지 않음"으로 화면에 올린다. 섀시를 어떤 id·어떤 값으로 등록하고, 섀시가 자기 자신을 슬롯 목록에서 빼는 규칙을 어떻게 두는 것이 안전한가(자기 id 를 코드에 박아 두기 / `Kind=chassis` 를 새로 두기 등). 공격자(가)가 이 규칙을 악용할 길이 있는가?

## 4. 1판의 질문 Q1~Q7 (그대로)

**Q1. D1 의 완화가 뚫리는 순서가 있는가?** 예: 서비스가 죽은 뒤 HKLM 에 남은 파이프 이름으로 공격자(가)가 서버를 세우는 경우(session 0 이 아니므로 거부된다고 봤다), session 0 에서 도는 다른 서비스가 그 이름을 여는 경우, 터미널 서비스·RDP 환경에서 session 0 판정이 달라지는 경우. `GetNamedPipeServerSessionId` 가 0 을 돌려주는데 서버가 실제로는 일반 사용자 프로세스인 경우가 있는가? 일반 권한에서 LocalSystem 서비스 프로세스에 `PROCESS_QUERY_LIMITED_INFORMATION` 이 실제로 거부되는지, 되는 경우·안 되는 경우를 아는 대로 적어 달라(공식 문서 이름과 함께).

**Q2. 앱형의 경로 대조를 속이는 방법이 있는가?** 공격자(가)가 등록된 진짜 실행 파일(예: `C:\Program Files\NetX\netx.exe`)을 직접 띄운 뒤 그 프로세스에 끼어들어 파이프를 열게 하면 경로는 일치한다 — 이것은 8.3 이 "못 막는 것"으로 적은 경우다. 그 밖에: 프로세스 하울링·도플갱잉으로 이미지 경로가 진짜처럼 보이는 경우, 파이프 핸들을 다른 프로세스에 넘겨(DuplicateHandle·상속) "만든 프로세스"와 "응답하는 프로세스"가 다른 경우, D4 의 PID 재사용. 각각 `GetNamedPipeServerProcessId`·`QueryFullProcessImageNameW` 가 무엇을 돌려주는가?

**Q3. 경로 비교(`names.rs`)가 다르다고 해야 할 것을 같다고 하거나 그 반대인 입력이 있는가?** 최종 경로를 받은 뒤 소문자로 바꿔 글자 비교한다. 대소문자 구분 폴더(WSL 용 설정), NTFS 의 대소문자 접기와 Rust `to_lowercase` 의 차이(터키어 İ, 독일어 ß, 전각 문자), 하드 링크(같은 파일의 다른 이름), 마운트 지점·`subst` 드라이브·네트워크 드라이브 문자, 볼륨 GUID 경로.

**Q4. HKCU 실행 중 값으로 섀시를 괴롭히는 순서(앱형).** 형식이 맞는 가짜 이름을 계속 써넣으면 섀시는 열기 실패나 서버 불일치를 되풀이한다(1차 반영으로 시도 간격 2초 이상, 화면에 "확인 실패"). 가짜 서버가 `open` 은 받아 주고 가만히 있으면? (서버 확인은 열기 직후 바로 끝나고 아무것도 보내지 않은 채 놓는다.) 섀시가 가짜 서버에 붙는 것 자체로 새는 정보가 있는가(식별 수준 토큰으로 서버가 알 수 있는 것: 사용자 SID 등)?

**Q5. 클라이언트(`client.rs`)가 깨지는 입력·순서.** id 를 지어낸 응답을 쏟아붓기, 같은 id 로 응답 두 번, 알림을 초당 수만 건(섀시 화면 쪽 초당 10건 상한 앞에서 읽기 스레드와 콜백이 버티는가), 1MB 에 조금 못 미치는 메시지를 연달아, 응답 없이 연결만 유지(호출 시한은 있다), `on_close` 가 불리기 전후의 호출 경쟁.

**Q6. 등록부 읽기.** `RegOpenKeyExW(HKLM, …, KEY_READ)` 를 기본 보기로 연다(64비트 프로세스 → 64비트 보기). 32비트 설치 프로그램(NSIS 기본)이 WOW6432Node 쪽에 쓰면 섀시가 못 본다 — 설치 프로그램이 64비트 보기에 쓰도록 강제하는 것이 맞는가, 섀시가 두 보기를 다 읽는 것이 맞는가(다 읽으면 생기는 문제는)? 하위 키 이름이 260자를 넘거나 UTF-16 이 깨진 경우는 건너뛴다.

**Q7. D2~D4 가운데 지금 고쳐야 할 것이 있는가?** 특히 D3: Program Files 아래라도 설치 프로그램이 폴더 권한을 느슨하게 만들었으면 바꿔치기가 된다. 섀시가 접속 때마다 실행 파일·폴더의 DACL 을 읽어 확인하는 것이 값어치가 있는가, 어떤 권한 비트를 봐야 하는가?

**Q8. Claude 가 못 본 것.** 3장의 C1~C7 과 위 Q1~Q7 에 없는 것 가운데, 부록의 코드에서 깨지는 입력·순서를 찾아 달라. 특히:

- `win.rs` 의 `reg_sz`·`WinRegistry::modules`: 등록부 값·키 이름으로 버퍼 길이 계산이 어긋나는 경우, HKCU 키가 등록부 연결(REG_LINK)인 경우.
- `win.rs` 의 `wait`·`PipeLine::read_line`·`PipeSink`: overlapped 한 번에 이벤트 하나를 돌려 쓰는 방식의 경쟁, `CancelIoEx` 가 다른 스레드의 쓰기까지 취소하는 순서, 읽기와 놓기(drop)가 겹칠 때 닫힌 핸들을 쓰는 순서.
- `open_unchecked` 의 `CreateFileW` 깃발: `SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION` 이 네임드 파이프에서 실제로 가장(impersonation)을 식별 수준으로 묶는가. 빠진 깃발이 있는가.
- `names.rs` 의 `norm_path`·`plain_absolute`·`under_admin_root`: 3-A 답변이 권한 `GetFullPathNameW` 를 쓰지 않고 `GetFinalPathNameByHandleW` 결과에 글자 비교를 했다. 이 선택으로 뚫리는 입력.
- `rpc.rs` 의 `depth_ok`·`parse_incoming`: 깊이 검사를 통과하지만 `serde_json` 을 느리게 하거나 메모리를 많이 쓰게 하는 1MB 안쪽 입력(아주 긴 수, 같은 키 되풀이, 큰 배열).
- `client.rs`: 기다리는 호출 표(`waiters`)를 불리는 순서, id 가 `i64` 범위를 넘는 응답, `Drop` 과 읽기 스레드의 순서.

## 5. 다음 단계(창 열기·인계)를 짜기 전에 — 통합 3차에서 넘어온 질문

「검증의뢰서 — 통합 3차」의 3-A 는 답을 받아 반영했다. 3-B 의 6·7번(제어 문자, 폭주), 3-C 의 9번(상태 거짓·시한), 4장(시각·id·재동기화)은 그 뒤 「답변반영 — 섀시 1차」와 「변경 제안 — 에피스틀 6장 (2판)」으로 정해졌다. **아직 답이 없는 것은 아래 셋이다.** 섀시 3단계(패널에서 모듈 창 열기, 모듈 사이 인계 중계)를 짜기 전에 필요하다. 이 부분은 아직 코드가 없으므로 설계에 대한 답이면 된다.

- **N1. 모듈이 준 "어디를 열지" 값을 섀시가 그대로 넘겨도 되는가.** 위젯·사건에는 `open: {view, ref}`(누르면 그 모듈의 어느 화면을 열지)와 `suggest: {intent, to}`(다른 모듈에 무엇을 넘기자는 제안)가 실린다. 감염된 모듈(나)이 `suggest.to` 를 다른 모듈로, `intent` 를 `firewall.block.request` 로, 대상을 정상 주소로 채워 보내면, 섀시 화면의 단추 하나로 **한 모듈이 다른 모듈에게 일을 시키는 모양**이 된다. 받는 모듈이 자기 확인 창으로 사람에게 다시 묻는다는 규칙(6.7, 6.8)만으로 충분한가? 섀시가 보여 줘야 할 것(누가 제안했는지, 무엇을 어디로 넘기는지)과 섀시가 거절해야 할 조합을 적어 달라.
- **N2. 인계를 받는 모듈은 "누가 보냈는지"를 무엇으로 아는가.** 섀시가 중계하면 파이프의 상대는 섀시다. 봉투의 `from` 칸은 섀시가 채운 글자일 뿐이다. 받는 모듈이 (가) 파이프 상대가 등록된 섀시인지, (나) 원래 제안한 모듈이 누구인지를 각각 무엇으로 확인하고, 화면에 무엇을 보여야 하는가. 섀시가 장악됐을 때 `from` 을 지어내는 것은 막을 수 없다고 보는데, 그때 피해를 줄이는 규칙은?
- **N3. 일반 권한 섀시가 장악됐을 때.** 섀시는 일반 권한이고 `read` 만 받는다. 그래도 인계의 시작 단추를 쥔다. 섀시 프로세스에 끼어든 코드가 모듈들에게 인계·제안을 연달아 보내 **확인 창을 쏟아 내** 사람이 무심코 누르게 만드는 순서를 막으려면, 받는 모듈 쪽에 어떤 상한(같은 대상 되풀이, 분당 건수, 쌓인 창 수)이 있어야 하는가.

## 6. 답변 형식

- 3장(C1~C7): 항목마다 **맞다 / 틀리다(근거) / 확인 못 함** → 고치는 법. C1 은 반드시 답해 달라.
- 4장(Q1~Q8)과 5장(N1~N3): 항목마다 **깨지는 입력·순서(구체적으로, 함수 이름과 함께)** → 영향 → 권고.
- 근거가 Windows 동작이면 Microsoft Learn 문서 이름. 확인하지 못한 것은 "추측".
- 맨 끝에 **지금 고쳐야 할 것 세 가지**를 급한 순서로.

```rust
//!
//! 접속 순서(`connect`): 파이프 열기(식별 수준 SQOS) → 서버 PID → **서버 확인** → 그 뒤에야 첫 바이트를 보낸다.

use std::sync::Arc;

/// 등록부에서 열거하는 하위 키 수의 상한
const MAX_KEYS: u32 = 64;

fn wide(s: &str) -> Vec<u16> {
    s.encode_utf16().chain(std::iter::once(0)).collect()
}

/// 닫히는 핸들
struct Owned(HANDLE);
impl Drop for Owned {
    fn drop(&mut self) {
        unsafe { CloseHandle(self.0) };
    }
}

/// 등록부의 글자열 값. 없거나, 글자열(REG_SZ)이 아니거나, 너무 길면 None. 값은 자료다 — 부르는 쪽이 형식을 검사한다
pub fn reg_sz(hive: HKEY, key: &str, value: &str) -> Option<String> {
    let (k, v) = (wide(key), wide(value));
    let mut buf = [0u16; 1024];
    let mut cb = (buf.len() * 2) as u32;
    // RRF_RT_REG_SZ: 다른 형식(REG_DWORD, REG_EXPAND_SZ …)이면 실패한다. 버퍼보다 길면 ERROR_MORE_DATA 로 실패한다
    let r = unsafe { RegGetValueW(hive, k.as_ptr(), v.as_ptr(), RRF_RT_REG_SZ, std::ptr::null_mut(), buf.as_mut_ptr() as *mut _, &mut cb) };
    if r != 0 {
        return None;
    }
    let n = (cb as usize / 2).min(buf.len());
    let s = String::from_utf16(&buf[..n]).ok()?;
    let s = s.trim_end_matches('\0').to_string();
    (!s.is_empty()).then_some(s)
}

/// 실제 등록부
pub struct WinRegistry;

impl RegistryView for WinRegistry {
    fn modules(&self) -> Vec<RawModule> {
        let mut out = Vec::new();
        let mut key: HKEY = std::ptr::null_mut();
        if unsafe { RegOpenKeyExW(HKEY_LOCAL_MACHINE, wide(MODULES_KEY).as_ptr(), 0, KEY_READ, &mut key) } != 0 {
            return out; // 키가 없음 = 등록된 모듈 없음
        }
        for i in 0..MAX_KEYS {
            let mut name = [0u16; 260];
            let mut len = name.len() as u32;
            let r = unsafe {
                RegEnumKeyExW(key, i, name.as_mut_ptr(), &mut len, std::ptr::null(), std::ptr::null_mut(), std::ptr::null_mut(), std::ptr::null_mut())
            };
            if r != 0 {
                break;
            }
            let Ok(id) = String::from_utf16(&name[..len as usize]) else { continue };
            // 형식이 틀린 이름은 값을 읽지도 않는다(이름이 경로 조각으로 쓰이므로)
            if !valid_module_id(&id) {
                continue;
            }
            let sub = format!(r"{MODULES_KEY}\{id}");
            out.push(RawModule {
                exe: reg_sz(HKEY_LOCAL_MACHINE, &sub, "Exe"),
                kind: reg_sz(HKEY_LOCAL_MACHINE, &sub, "Kind"),
                api: reg_sz(HKEY_LOCAL_MACHINE, &sub, "Api"),
                pipe_name: reg_sz(HKEY_LOCAL_MACHINE, &sub, "PipeName"),
                id,
            });
        }
        unsafe { RegCloseKey(key) };
        out
    }

    fn running_pipe(&self, id: &str) -> Option<String> {
        if !valid_module_id(id) {
            return None;
        }
        reg_sz(HKEY_CURRENT_USER, &format!(r"{RUNNING_KEY}\{id}"), "PipeName")
    }
}

/// 운영체제가 알려 주는 최종 경로(짧은 이름·링크를 푼 것, 8.3 의 5번). 파일을 열 수 없으면 None
pub fn final_path(path: &str) -> Option<String> {
    let w = wide(path);
    // 권한 0 으로 연다(속성만) — 읽기 권한이 없어도 경로는 얻는다
    let h = unsafe {
        CreateFileW(w.as_ptr(), 0, FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE, std::ptr::null(), OPEN_EXISTING, FILE_FLAG_BACKUP_SEMANTICS, std::ptr::null_mut())
    };
    if h == INVALID_HANDLE_VALUE {
        return None;
    }
    let h = Owned(h);
    let mut buf = vec![0u16; 2048];
    let n = unsafe { GetFinalPathNameByHandleW(h.0, buf.as_mut_ptr(), buf.len() as u32, FILE_NAME_NORMALIZED | VOLUME_NAME_DOS) } as usize;
    if n == 0 || n >= buf.len() {
        return None;
    }
    String::from_utf16(&buf[..n]).ok()
}

/// Program Files 폴더들 — 환경 변수가 아니라 운영체제에 묻는다(환경 변수는 실행한 쪽이 바꿀 수 있다)
pub fn admin_roots() -> Vec<String> {
    let mut out = Vec::new();
    for id in [&FOLDERID_ProgramFiles, &FOLDERID_ProgramFilesX86] {
        let mut p: *mut u16 = std::ptr::null_mut();
        let hr = unsafe { SHGetKnownFolderPath(id, 0, std::ptr::null_mut(), &mut p) };
        if hr >= 0 && !p.is_null() {
            let mut n = 0usize;
            while unsafe { *p.add(n) } != 0 && n < 4096 {
                n += 1;
            }
            if let Ok(s) = String::from_utf16(unsafe { std::slice::from_raw_parts(p, n) }) {
                if !out.contains(&s) {
                    out.push(s);
                }
            }
        }
        if !p.is_null() {
            unsafe { CoTaskMemFree(p as *const _) };
        }
    }
    out
}

/// 실제 PC
pub struct WinHost;
impl Host for WinHost {
    fn final_path(&self, path: &str) -> Option<String> {
        final_path(path)
    }
    fn admin_roots(&self) -> Vec<String> {
        // 폴더 자체도 최종 경로로 맞춘다
        admin_roots().iter().filter_map(|r| final_path(r)).collect()
    }
}

/// 프로세스의 실행 파일 전체 경로. 핸들을 먼저 잡고 그 핸들로 읽는다(PID 재사용 틈, 8.3). 열 권한이 없으면 None
pub fn process_image(pid: u32) -> Option<String> {
    let h = unsafe { OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION, 0, pid) };
    if h.is_null() {
        return None;
    }
    let h = Owned(h);
    let mut buf = vec![0u16; 2048];
    let mut n = buf.len() as u32;
    if unsafe { QueryFullProcessImageNameW(h.0, PROCESS_NAME_WIN32, buf.as_mut_ptr(), &mut n) } == 0 {
        return None;
    }
    String::from_utf16(&buf[..n as usize]).ok()
}

/// 파이프를 열고 (핸들, 서버 PID) 를 돌려준다. **서버가 누구인지는 확인하지 않는다** — `verify_server` 가 한다.
///
/// - SQOS 를 식별 수준으로 건다: 서버가 우리 토큰으로 행동(가장)하지 못한다.
/// - GENERIC_WRITE 대신 개별 권한만 청한다: 서버 DACL 은 인스턴스 만들기(FILE_CREATE_PIPE_INSTANCE)를 주지 않는다.
/// - overlapped 로 연다: 동기 핸들을 읽기·쓰기 두 스레드가 나눠 쓰면 대기 중인 읽기가 쓰기를 막는다(스토리방화벽 A22 실측).
pub fn open_unchecked(name: &str) -> std::io::Result<(Arc<Handle>, u32)> {
    let w = wide(name);
    let mut tries = 0;
    let h = loop {
        let access = FILE_GENERIC_READ | FILE_WRITE_DATA | FILE_WRITE_ATTRIBUTES;
        let h = unsafe {
            CreateFileW(
                w.as_ptr(),
                access,
                FILE_SHARE_NONE,
                std::ptr::null(),
                OPEN_EXISTING,
                FILE_FLAG_OVERLAPPED | SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION,
                std::ptr::null_mut(),
            )
        };
        if h != INVALID_HANDLE_VALUE {
            break h;
        }
        let err = std::io::Error::last_os_error();
        // 서버의 빈 인스턴스가 잠시 없으면 최대 3번, 2초씩 기다린다
        if err.raw_os_error() == Some(ERROR_PIPE_BUSY) && tries < 3 {
            tries += 1;
            unsafe { WaitNamedPipeW(w.as_ptr(), 2000) };
            continue;
        }
        return Err(err);
    };
    let handle = Arc::new(Handle(h));
    let mut spid = 0u32;
    if unsafe { GetNamedPipeServerProcessId(h, &mut spid) } == 0 {
        return Err(std::io::Error::last_os_error());
    }
    let mut mode = PIPE_READMODE_MESSAGE;
    if unsafe { SetNamedPipeHandleState(h, &mut mode, std::ptr::null(), std::ptr::null()) } == 0 {
        return Err(std::io::Error::last_os_error());
    }
    Ok((handle, spid))
}

struct Event(HANDLE);
unsafe impl Send for Event {}
impl Event {
    fn new() -> std::io::Result<Self> {
        let e = unsafe { CreateEventW(std::ptr::null(), 1, 0, std::ptr::null()) };
        if e.is_null() {
            return Err(std::io::Error::last_os_error());
        }
        Ok(Event(e))
    }
}
impl Drop for Event {
    fn drop(&mut self) {
        unsafe { CloseHandle(self.0) };
    }
}

/// overlapped 한 번을 끝까지 기다린다. 돌려주는 값: 메시지가 더 남았는가
fn wait(h: HANDLE, ov: &mut OVERLAPPED, started_ok: bool, n: &mut u32) -> std::io::Result<bool> {
    if !started_ok {
        let e = unsafe { GetLastError() };
        if e == ERROR_MORE_DATA {
            return Ok(true);
        }
        if e != ERROR_IO_PENDING {
            return Err(std::io::Error::from_raw_os_error(e as i32));
        }
    }
    if unsafe { GetOverlappedResult(h, ov, n, 1) } == 0 {
        let e = unsafe { GetLastError() };
        if e == ERROR_MORE_DATA {
            return Ok(true);
        }
        return Err(std::io::Error::from_raw_os_error(e as i32));
    }
    Ok(false)
}

pub struct PipeLine {
    h: Arc<Handle>,
    ev: Event,
    buf: Vec<u8>,
}
impl PipeLine {
    pub fn new(h: Arc<Handle>) -> std::io::Result<Self> {
        // 상한보다 조금 큰 버퍼 하나로 메시지를 통째로 받는다(스토리방화벽 화면과 같은 방식)
        Ok(Self { h, ev: Event::new()?, buf: vec![0u8; MAX_LINE + 4096] })
    }
}
impl LineSource for PipeLine {
    fn read_line(&mut self) -> std::io::Result<Option<Vec<u8>>> {
        // 메시지 모드: 한 번 읽기 = 메시지 하나. 버퍼에 다 들어오지 않으면(ERROR_MORE_DATA) 상한을 넘은 것이므로 끝낸다.
        // (러너 실측 run-1: 작은 버퍼로 이어 읽으면, 곧바로 ERROR_MORE_DATA 로 돌아온 첫 조각의 길이를 얻지 못해 조각을 잃었다)
        let mut ov: OVERLAPPED = unsafe { std::mem::zeroed() };
        ov.hEvent = self.ev.0;
        let mut n = 0u32;
        let ok = unsafe { ReadFile(self.h.0, self.buf.as_mut_ptr(), self.buf.len() as u32, &mut n, &mut ov) } != 0;
        match wait(self.h.0, &mut ov, ok, &mut n) {
            Ok(true) => Err(std::io::Error::new(std::io::ErrorKind::InvalidData, "메시지가 상한을 넘음")),
            Ok(false) if n as usize > MAX_LINE => Err(std::io::Error::new(std::io::ErrorKind::InvalidData, "메시지가 상한을 넘음")),
            Ok(false) => Ok(if n == 0 { None } else { Some(self.buf[..n as usize].to_vec()) }),
            // 끊김·취소 = 끝
            Err(e) if matches!(e.raw_os_error(), Some(ERROR_BROKEN_PIPE) | Some(ERROR_OPERATION_ABORTED)) => Ok(None),
            Err(e) => Err(e),
        }
    }
}

pub struct PipeSink {
    h: Arc<Handle>,
    ev: Event,
}
impl PipeSink {
    pub fn new(h: Arc<Handle>) -> std::io::Result<Self> {
        Ok(Self { h, ev: Event::new()? })
    }
}
impl LineSink for PipeSink {
    fn write_line(&mut self, line: &[u8]) -> std::io::Result<()> {
        let mut ov: OVERLAPPED = unsafe { std::mem::zeroed() };
        ov.hEvent = self.ev.0;
        let mut n = 0u32;
        let ok = unsafe { WriteFile(self.h.0, line.as_ptr(), line.len() as u32, &mut n, &mut ov) } != 0;
        wait(self.h.0, &mut ov, ok, &mut n)?;
        if n as usize != line.len() {
            return Err(std::io::Error::new(std::io::ErrorKind::WriteZero, "짧은 쓰기"));
        }
        Ok(())
    }
}
impl Drop for PipeSink {
    fn drop(&mut self) {
        // 읽기 스레드의 대기 중인 ReadFile 을 취소해 스레드가 끝나고 핸들이 닫히게 한다(서버가 끊김을 본다)
        unsafe { CancelIoEx(self.h.0, std::ptr::null()) };
    }
}

            ConnectError::ServerMismatch => "파이프의 상대가 등록된 프로그램이 아니어서 접속하지 않았습니다",
            ConnectError::NotSession0 => "파이프의 상대가 서비스(session 0)가 아니어서 접속하지 않았습니다",
        }
    }
}

/// 서버 확인이 어디까지 됐는가
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Verified {
    /// 파이프 서버 프로세스의 실행 파일이 등록된 Exe 와 같음을 확인했다.
    /// false 는 서비스형에서만 나온다: 일반 권한으로는 서비스 프로세스를 열지 못할 수 있어, 그때는
    /// "관리자만 쓰는 HKLM 에 공개된 파이프 이름 + session 0" 으로 확인한 것이다.
    pub image_checked: bool,
}

/// 파이프 서버 확인(5.2 의 3번, 8.3 의 3번). 통과하기 전에는 아무것도 보내지 않는다.
///
/// - 앱형: 서버 프로세스의 실행 파일(최종 경로)이 등록된 Exe 와 같아야 한다. 알아내지 못하면 거부.
/// - 서비스형: 서버가 session 0 이어야 한다(일반 사용자 프로세스는 session 0 에서 돌 수 없다 — 서비스가 죽은 뒤
///   남은 이름으로 가짜 서버를 세우는 것을 막는다). 실행 파일을 알아낼 수 있으면 등록된 Exe 와 같아야 한다.
pub fn verify_server(h: &Handle, server_pid: u32, kind: ModuleKind, exe_final: &str) -> Result<Verified, ConnectError> {
    let image = process_image(server_pid).and_then(|p| final_path(&p));
    if let Some(img) = &image {
        if !same_path(img, exe_final) {
            return Err(ConnectError::ServerMismatch);
        }
    }
    match kind {
        ModuleKind::Service => {
            let mut sess = u32::MAX;
            // 세션은 파이프 핸들에서 바로 얻는다(프로세스를 열 권한이 없어도 된다)
            let known = unsafe { GetNamedPipeServerSessionId(h.0, &mut sess) } != 0;
            if !(known && sess == 0) {
                return Err(ConnectError::NotSession0);
            }
            Ok(Verified { image_checked: image.is_some() })
        }
        _ => {
            if image.is_none() {
                return Err(ConnectError::ServerUnknown);
            }
            Ok(Verified { image_checked: true })
        }
    }
}

/// 슬롯에 붙는다: 열기 → 서버 확인 → 클라이언트 시작. rack.hello 는 부르는 쪽이 한다.
pub fn connect(
    slot: &Slot,
    on_notify: Box<dyn Fn(&str, serde_json::Value) + Send>,
    on_close: Box<dyn FnOnce(CloseReason) + Send>,
) -> Result<(Client, Verified), ConnectError> {
    let SlotState::Running { pipe } = &slot.state else {
        return Err(ConnectError::NotRunning);
    };
    let (h, spid) = open_unchecked(pipe).map_err(|e| ConnectError::Open(e.to_string()))?;
    let verified = verify_server(&h, spid, slot.kind, &slot.exe_final)?;
    let source = PipeLine::new(h.clone()).map_err(|e| ConnectError::Open(e.to_string()))?;
    let sink = PipeSink::new(h).map_err(|e| ConnectError::Open(e.to_string()))?;
    Ok((Client::start(Box::new(source), Box::new(sink), on_notify, on_close), verified))
}
```

```rust
//! 등록부 자리, 파이프 이름 형식, 경로 비교. 순수 함수 — Linux 에서 시험한다.
//! 경로 비교·형식 검사는 스토리방화벽 `crates/rack`(실기기·러너에서 확인된 것)과 같은 규칙이다.

/// 설치 프로그램(관리자)이 쓰는 자리: `HKLM\SOFTWARE\Antioch\Modules\<id>` — 값 Exe, ClientExe, Kind, Api, (서비스형) PipeName
pub const MODULES_KEY: &str = r"SOFTWARE\Antioch\Modules";
/// 앱형 모듈이 실행 중일 때 쓰는 자리: `HKCU\SOFTWARE\Antioch\Running\<id>` — 값 PipeName
pub const RUNNING_KEY: &str = r"SOFTWARE\Antioch\Running";

/// 파이프 이름: `\\.\pipe\<id>-<128비트 hex>` (설계 5.1). 다른 모양은 쓰지 않는다 —
/// 등록부 값으로 남의 파이프나 다른 PC(`\\server\pipe\…`)에 붙게 만들 수 없다.
pub fn valid_pipe_name(id: &str, name: &str) -> bool {
    let Some(rest) = name.strip_prefix(r"\\.\pipe\") else {
        return false;
    };
    let Some(hex) = rest.strip_prefix(id).and_then(|r| r.strip_prefix('-')) else {
        return false;
    };
    hex.len() == 32 && hex.bytes().all(|c| c.is_ascii_hexdigit())
}

/// 비교용 모양: `\\?\` 접두사 제거, `/` → `\`, 소문자, 끝의 `\` 제거.
/// 짧은 이름·링크는 여기서 풀지 않는다 — 운영체제의 최종 경로(GetFinalPathNameByHandle)를 받은 뒤에 부른다.
pub fn norm_path(p: &str) -> String {
    let p = p.trim();
    let p = p
        .strip_prefix(r"\\?\UNC\")
        .map(|r| format!(r"\\{r}"))
        .unwrap_or_else(|| p.strip_prefix(r"\\?\").unwrap_or(p).to_string());
    let mut s: String = p.replace('/', r"\").to_lowercase();
    while s.len() > 3 && s.ends_with('\\') {
        s.pop();
    }
    s
}

/// 드라이브 문자로 시작하는 절대 경로이고 `.`·`..` 마디와 대체 데이터 스트림(`:`)이 없다
fn plain_absolute(p: &str) -> bool {
    let b = p.as_bytes();
    b.len() > 3
        && b[0].is_ascii_alphabetic()
        && b[1] == b':'
        && b[2] == b'\\'
        && !p[2..].contains(':')
        && !p.split('\\').any(|seg| seg == ".." || seg == ".")
}

/// 두 경로가 같은 파일을 가리키는가(둘 다 최종 경로일 때). 빈 값·절대 경로가 아닌 값은 같다고 하지 않는다
pub fn same_path(a: &str, b: &str) -> bool {
    let (a, b) = (norm_path(a), norm_path(b));
    plain_absolute(&a) && a == b
}

/// 실행 파일이 관리자만 쓸 수 있는 폴더(Program Files 등) 아래인가 (8.3 의 4번)
pub fn under_admin_root(exe: &str, roots: &[String]) -> bool {
    let e = norm_path(exe);
    if !plain_absolute(&e) {
        return false;
    }
    roots
        .iter()
        .map(|r| norm_path(r))
        .filter(|r| plain_absolute(r))
        .any(|r| e.len() > r.len() + 1 && e.starts_with(&r) && e.as_bytes()[r.len()] == b'\\')
}
```

```rust
//! 슬롯 발견 (설계 5장, 8.3 확정). 등록부를 읽는 일과 판단을 나눴다:
//! 읽기는 `RegistryView`/`Host`(Windows 구현은 `win`), 판단은 여기 — 순수 함수라 Linux 에서 시험한다.

#[derive(Debug, Clone, Default)]
pub struct RawModule {

            Distrust::BadKind => "등록 정보의 종류(Kind) 값이 올바르지 않습니다",

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum SlotState {

    Off,

#[derive(Debug, Clone, PartialEq, Eq)]

    pub exe_final: String,
    pub state: SlotState,

fn parse_api(s: &str) -> Option<(u32, u32)> {
    let (a, b) = s.trim().split_once('.')?;
    Some((a.parse().ok()?, b.parse().ok()?))
}

/// 등록부를 읽어 슬롯 목록을 만든다.
/// - id 형식이 틀린 등록(대문자 포함)과 중복은 뺀다.
/// - 서비스형의 파이프 이름은 HKLM 값만, 앱형은 HKCU 값만 본다. HKLM 에 등록되지 않은 id 의 HKCU 값은 읽지도 않는다.
pub fn discover(reg: &dyn RegistryView, host: &dyn Host) -> Vec<Slot> {
    let roots = host.admin_roots();
    let mut out: Vec<Slot> = Vec::new();
    for m in reg.modules() {
        if out.len() >= MAX_SLOTS {
            break;
        }
        if !valid_module_id(&m.id) || out.iter().any(|s| s.id == m.id) {
            continue;
        }
        let kind = match m.kind.as_deref().map(str::trim) {
            Some("service") => ModuleKind::Service,
            Some("app") => ModuleKind::App,
            _ => {
                out.push(Slot { id: m.id, kind: ModuleKind::App, exe_final: String::new(), state: SlotState::Untrusted(Distrust::BadKind) });
                continue;
            }
        };
        let untrusted = |why, exe_final: String| Slot { id: m.id.clone(), kind, exe_final, state: SlotState::Untrusted(why) };

        let Some(exe_final) = m.exe.as_deref().and_then(|e| host.final_path(e)) else {
            out.push(untrusted(Distrust::ExeMissing, String::new()));
            continue;
        };
        if !under_admin_root(&exe_final, &roots) {
            out.push(untrusted(Distrust::NotAdminFolder, exe_final));
            continue;
        }
        // Api 값이 있으면 메이저를 본다. 없으면 rack.hello 의 판 협상에 맡긴다
        if let Some(api) = m.api.as_deref() {
            if parse_api(api).map(|a| a.0) != Some(EPISTLE_API.0) {
                out.push(untrusted(Distrust::ApiMismatch, exe_final));
                continue;
            }
        }
        let pipe = match kind {
            ModuleKind::Service => m.pipe_name.clone(),
            _ => reg.running_pipe(&m.id),
        };
        let state = match pipe {
            None => SlotState::Off,
            Some(p) if valid_pipe_name(&m.id, &p) => SlotState::Running { pipe: p },
            Some(_) => SlotState::Untrusted(Distrust::BadPipeName),
        };
        out.push(Slot { id: m.id, kind, exe_final, state });
    }
    out
}
```

```rust
//! 모듈에 붙는 쪽의 클라이언트. 전송(파이프)은 `LineSource`/`LineSink` 뒤에 있어 Linux 에서 메모리 전송으로 시험한다.
//! 읽기 스레드 하나가 응답(id 있음)은 기다리는 호출에게, 알림(id 없음)은 콜백으로 넘긴다.
//! (구조는 스토리방화벽 화면의 client.rs — 러너와 실기기에서 확인된 것 — 을 따랐다.)

use std::collections::HashMap;
use std::sync::atomic::{AtomicBool, Ordering};
use std::sync::mpsc::{self, RecvTimeoutError, Sender};
use std::sync::{Arc, Mutex};
use std::time::Duration;

use serde_json::Value;

use crate::rpc::{self, BadLine, Incoming, RpcError};
use crate::{api_compatible, HelloReply, EPISTLE_API};

/// 한 메시지(한 줄)를 읽는다. `Ok(None)` = 상대가 닫음. 상한(rpc::MAX_LINE)을 넘는 메시지는 Err 로 끝낸다
pub trait LineSource: Send {
    fn read_line(&mut self) -> std::io::Result<Option<Vec<u8>>>;
}
/// 한 메시지(한 줄)를 쓴다. 놓일(drop) 때 읽기 쪽의 대기를 풀어 주어야 한다
pub trait LineSink: Send {
    fn write_line(&mut self, line: &[u8]) -> std::io::Result<()>;
}

/// 모양이 틀린 줄을 이만큼 받으면 연결을 끊는다(쓰레기를 쏟아붓는 상대)
pub const MAX_BAD_LINES: u32 = 8;

#[derive(Debug, Clone, PartialEq)]
pub enum CallError {
    /// 시한 안에 답이 없음
    Timeout,
    /// 연결이 끊김
    Closed,
    /// 보내지 못함
    Send(String),
    /// 모듈이 오류로 답함
    Rpc(RpcError),
}

/// 연결이 끝난 까닭
#[derive(Debug, Clone, PartialEq)]
pub enum CloseReason {
    /// 상대가 닫음
    Eof,
    /// 읽기 오류(상한을 넘는 메시지 포함)
    Read(String),
    /// 모양이 틀린 줄이 너무 많음
    Garbage,
}

type Waiters = Arc<Mutex<HashMap<i64, Sender<Result<Value, RpcError>>>>>;

pub struct Client {
    sink: Mutex<Box<dyn LineSink>>,
    next_id: Mutex<i64>,
    waiters: Waiters,
    /// 우리가 놓는 중 — 읽기 스레드가 끊김 콜백을 부르지 않게
    closing: Arc<AtomicBool>,
    closed: Arc<AtomicBool>,
}

impl Drop for Client {
    fn drop(&mut self) {
        // 필드(sink)는 이 함수 뒤에 놓인다 → 깃발이 먼저 선다
        self.closing.store(true, Ordering::SeqCst);
    }
}

impl Client {
    /// `on_notify(method, params)`: 알림. `on_close(reason)`: 상대 쪽 사정으로 끊겼을 때 한 번(우리가 놓은 경우는 부르지 않는다).
    /// 두 콜백은 읽기 스레드에서 불린다 — 오래 붙잡지 않는다.
    pub fn start(
        mut source: Box<dyn LineSource>,
        sink: Box<dyn LineSink>,
        on_notify: Box<dyn Fn(&str, Value) + Send>,
        on_close: Box<dyn FnOnce(CloseReason) + Send>,
    ) -> Client {
        let waiters: Waiters = Arc::new(Mutex::new(HashMap::new()));
        let closing = Arc::new(AtomicBool::new(false));
        let closed = Arc::new(AtomicBool::new(false));
        let (w, closing2, closed2) = (waiters.clone(), closing.clone(), closed.clone());
        std::thread::spawn(move || {
            let mut bad = 0u32;
            let reason = loop {
                let line = match source.read_line() {
                    Ok(Some(l)) => l,
                    Ok(None) => break CloseReason::Eof,
                    Err(e) => break CloseReason::Read(e.to_string()),
                };
                match rpc::parse_incoming(trim(&line)) {
                    Ok(Incoming::Response { id, result }) => {
                        // 기다리는 호출이 없는 id(시한이 지난 답, 지어낸 id)는 버린다
                        if let Some(tx) = w.lock().unwrap().remove(&id) {
                            let _ = tx.send(result);
                        }
                    }
                    Ok(Incoming::Notification { method, params }) => on_notify(&method, params),
                    Err(BadLine::TooLong) => break CloseReason::Read("메시지가 상한을 넘음".into()),
                    Err(_) => {
                        bad += 1;
                        if bad >= MAX_BAD_LINES {
                            break CloseReason::Garbage;
                        }
                    }
                }
            };
            closed2.store(true, Ordering::SeqCst);
            // 기다리던 호출을 모두 깨운다(보내는 쪽이 사라지면 recv 가 Closed 로 끝난다)
            w.lock().unwrap().clear();
            if !closing2.load(Ordering::SeqCst) {
                on_close(reason);
            }
        });
        Client { sink: Mutex::new(sink), next_id: Mutex::new(1), waiters, closing, closed }
    }

    pub fn is_closed(&self) -> bool {
        self.closed.load(Ordering::SeqCst)
    }

    /// 요청을 보내고 답을 기다린다. `params` 는 객체
    pub fn call(&self, method: &str, params: Value, timeout: Duration) -> Result<Value, CallError> {
        if self.is_closed() {
            return Err(CallError::Closed);
        }
        let id = {
            let mut n = self.next_id.lock().unwrap();
            let id = *n;
            *n += 1;
            id
        };
        let (tx, rx) = mpsc::channel();
        self.waiters.lock().unwrap().insert(id, tx);
        let line = rpc::request_line(id, method, params);
        if let Err(e) = self.sink.lock().unwrap().write_line(line.as_bytes()) {
            self.waiters.lock().unwrap().remove(&id);
            return Err(CallError::Send(e.to_string()));
        }
        match rx.recv_timeout(timeout) {
            Ok(Ok(v)) => Ok(v),
            Ok(Err(e)) => Err(CallError::Rpc(e)),
            Err(RecvTimeoutError::Timeout) => {
                self.waiters.lock().unwrap().remove(&id);
                Err(CallError::Timeout)
            }
            Err(RecvTimeoutError::Disconnected) => Err(CallError::Closed),
        }
    }

    /// rack.hello: 판을 맞추고, 답한 모듈 이름이 등록부의 슬롯 id 와 같은지 본다(변경 제안 2판 2장)
    pub fn hello(&self, slot_id: &str, client_version: &str, timeout: Duration) -> Result<HelloReply, HelloError> {
        let params = serde_json::json!({"client": "antioch", "client_version": client_version, "api": [EPISTLE_API.0, EPISTLE_API.1]});
        let v = self.call("rack.hello", params, timeout).map_err(HelloError::Call)?;
        let reply: HelloReply = serde_json::from_value(v).map_err(|_| HelloError::Malformed)?;
        if reply.module != slot_id {
            return Err(HelloError::WrongModule);
        }
        if !api_compatible(reply.api) {
            return Err(HelloError::ApiMismatch);
        }
        Ok(reply)
    }
}

#[derive(Debug, Clone, PartialEq)]
pub enum HelloError {
    Call(CallError),
    Malformed,
    /// 등록부의 슬롯과 다른 이름으로 답함
    WrongModule,
    ApiMismatch,
}

fn trim(line: &[u8]) -> &[u8] {
    let mut l = line;
    while let [rest @ .., b'\n' | b'\r' | b' '] = l {
        l = rest;
    }
    l
}

/// 시험용 메모리 전송: 한쪽은 클라이언트에 끼우고, 다른 쪽(`Peer`)이 모듈 흉내를 낸다
pub mod mem {
    use super::{LineSink, LineSource};
    use std::sync::mpsc::{self, Receiver, RecvTimeoutError, Sender};
    use std::time::Duration;

    pub struct Source(Receiver<Option<Vec<u8>>>);
    impl LineSource for Source {
        fn read_line(&mut self) -> std::io::Result<Option<Vec<u8>>> {
            match self.0.recv() {
                Ok(Some(l)) if l.len() > crate::rpc::MAX_LINE => Err(std::io::Error::new(std::io::ErrorKind::InvalidData, "메시지가 상한을 넘음")),
                Ok(l) => Ok(l),
                Err(_) => Ok(None),
            }
        }
    }
    pub struct Sink {
        tx: Sender<Vec<u8>>,
        /// 놓일 때 읽기 쪽을 깨운다
        wake: Sender<Option<Vec<u8>>>,
    }
    impl LineSink for Sink {
        fn write_line(&mut self, line: &[u8]) -> std::io::Result<()> {
            self.tx.send(line.to_vec()).map_err(|_| std::io::Error::new(std::io::ErrorKind::BrokenPipe, "상대가 닫음"))
        }
    }
    impl Drop for Sink {
        fn drop(&mut self) {
            let _ = self.wake.send(None);
        }
    }

    /// 모듈 쪽
    pub struct Peer {
        rx: Receiver<Vec<u8>>,
        tx: Sender<Option<Vec<u8>>>,
    }
    impl Peer {
        /// 클라이언트가 보낸 다음 요청(JSON). 2초 안에 없으면 None
        pub fn next_request(&self) -> Option<serde_json::Value> {
            match self.rx.recv_timeout(Duration::from_secs(2)) {
                Ok(l) => serde_json::from_slice(&l).ok(),
                Err(RecvTimeoutError::Timeout) | Err(RecvTimeoutError::Disconnected) => None,
            }
        }
        pub fn send_raw(&self, line: &[u8]) {
            let _ = self.tx.send(Some(line.to_vec()));
        }
        pub fn send(&self, v: serde_json::Value) {
            self.send_raw(format!("{v}\n").as_bytes());
        }
        pub fn close(&self) {
            let _ = self.tx.send(None);
        }
        /// 클라이언트가 연결을 놓았는가(보내는 쪽이 사라짐)
        pub fn client_gone(&self) -> bool {
            matches!(self.rx.recv_timeout(Duration::from_secs(2)), Err(RecvTimeoutError::Disconnected))
        }
    }

    pub fn pair() -> (Box<Source>, Box<Sink>, Peer) {
        let (to_client, client_rx) = mpsc::channel();
        let (to_peer, peer_rx) = mpsc::channel();
        (Box::new(Source(client_rx)), Box::new(Sink { tx: to_peer, wake: to_client.clone() }), Peer { rx: peer_rx, tx: to_client })
    }
}
```

```rust
//! 봉투: 한 줄 JSON-RPC 2.0 (설계 6.1 확정). 접속하는 쪽(섀시)이 쓰는 부분만 있다.
//! 받은 줄은 해석하기 전에 길이와 중첩 깊이를 본다 — 모듈이 보낸 것은 자료이고, 해석기를 지치게 하는 입력일 수 있다.

use serde_json::Value;

/// 한 줄(메시지 하나)의 상한. 6.1 의 "요청 1MB 상한"을 응답·알림에도 같이 쓴다 [제안 — 6.1 은 요청만 적었다]
pub const MAX_LINE: usize = 1024 * 1024;
/// 중첩 깊이 상한. rack.* 응답은 깊이 6을 넘지 않는다
pub const MAX_DEPTH: usize = 32;

pub const VERSION_MISMATCH: i64 = -32006;
pub const UNAUTHORIZED: i64 = -32001;
pub const METHOD_NOT_FOUND: i64 = -32601;

#[derive(Debug, Clone, PartialEq)]
pub struct RpcError {
    pub code: i64,
    pub message: String,
}

#[derive(Debug, Clone, PartialEq)]
pub enum Incoming {
    /// 요청에 대한 답
    Response { id: i64, result: Result<Value, RpcError> },
    /// 서버가 밀어 주는 알림(id 없음)
    Notification { method: String, params: Value },
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum BadLine {
    TooLong,
    TooDeep,
    NotJson,
    /// JSON 이지만 JSON-RPC 2.0 응답·알림 모양이 아니다(우리에게 온 요청 포함 — 섀시는 요청을 받지 않는다)
    NotRpc,
}

/// 요청 한 줄(끝에 개행). params 는 객체여야 한다(6.1)
pub fn request_line(id: i64, method: &str, params: Value) -> String {
    debug_assert!(params.is_object());
    let mut s = serde_json::json!({"jsonrpc": "2.0", "id": id, "method": method, "params": params}).to_string();
    s.push('\n');
    s
}

/// 문자열 밖의 `{`·`[` 중첩이 상한 안인가. 해석 전에 바이트만 훑는다
pub fn depth_ok(line: &[u8], max: usize) -> bool {
    let (mut depth, mut in_str, mut esc) = (0usize, false, false);
    for &b in line {
        if in_str {
            if esc {
                esc = false;
            } else if b == b'\\' {
                esc = true;
            } else if b == b'"' {
                in_str = false;
            }
            continue;
        }
        match b {
            b'"' => in_str = true,
            b'{' | b'[' => {
                depth += 1;
                if depth > max {
                    return false;
                }
            }
            b'}' | b']' => depth = depth.saturating_sub(1),
            _ => {}
        }
    }
    true
}

/// 받은 한 줄을 응답 또는 알림으로 읽는다
pub fn parse_incoming(line: &[u8]) -> Result<Incoming, BadLine> {
    if line.len() > MAX_LINE {
        return Err(BadLine::TooLong);
    }
    if !depth_ok(line, MAX_DEPTH) {
        return Err(BadLine::TooDeep);
    }
    let v: Value = serde_json::from_slice(line).map_err(|_| BadLine::NotJson)?;
    let obj = v.as_object().ok_or(BadLine::NotRpc)?;
    if obj.get("jsonrpc").and_then(Value::as_str) != Some("2.0") {
        return Err(BadLine::NotRpc);
    }
    match (obj.get("id"), obj.get("method")) {
        // 알림: method 있고 id 없음
        (None, Some(m)) => {
            let method = m.as_str().ok_or(BadLine::NotRpc)?;
            if method.is_empty() || method.len() > 64 || !method.bytes().all(|c| c.is_ascii_alphanumeric() || c == b'.' || c == b'_') {
                return Err(BadLine::NotRpc);
            }
            Ok(Incoming::Notification { method: method.to_string(), params: obj.get("params").cloned().unwrap_or(Value::Null) })
        }
        // 응답: id 있고 method 없음, result 와 error 가운데 하나
        (Some(id), None) => {
            let id = id.as_i64().ok_or(BadLine::NotRpc)?;
            match (obj.get("result"), obj.get("error")) {
                (Some(r), None) => Ok(Incoming::Response { id, result: Ok(r.clone()) }),
                (None, Some(e)) => {
                    let code = e.get("code").and_then(Value::as_i64).ok_or(BadLine::NotRpc)?;
                    let message: String = e.get("message").and_then(Value::as_str).unwrap_or("").chars().take(200).collect();
                    Ok(Incoming::Response { id, result: Err(RpcError { code, message }) })
                }
                _ => Err(BadLine::NotRpc),
            }
        }
        _ => Err(BadLine::NotRpc),
    }
}
```
